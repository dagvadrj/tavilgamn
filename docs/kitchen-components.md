# Гал тогоо: суурилуулсан зуух ба бүрэлдэхүүний panel

## Ажиллуулах заавар

Энэ өөрчлөлт ProjectN2-ийн одоогийн Next.js 14 / React 18 / React Three Fiber 8 / Three.js 0.170 төсөлд зориулагдсан. UI нь Tailwind болон өөрийн CSS; shadcn болон шинэ dependency нэмээгүй.

Энэ workspace-д код аль хэдийн шинэчлэгдсэн. Өөр хуулбарт суулгахдаа `patches/kitchen-components-code.zip` доторх файлуудыг төслийн үндсэн хавтас руу замын бүтцийг нь хадгалан хуулна. Эсвэл өмнөх ижил хувилбар дээр incremental patch хэрэглэнэ. ZIP ба patch-ийг хоёуланг нь давхар хэрэглэхгүй.

```powershell
git apply --check patches/kitchen-components.patch
git apply patches/kitchen-components.patch
npm ci
npm run dev
```

`http://localhost:3000/kitchen` хаягаар нээнэ. `npm ci` нь зөвхөн dependencies суулгаагүй шинэ хуулбарт шаардлагатай.

Шалгалт:

```powershell
npm test
npm run typecheck
npm run lint
npm run build
```

`next/font` одоогийн Inter/Fraunces font-ийг Google Fonts-оос татдаг тул эхний build-д интернэт хэрэгтэй.

## Ашиглах

1. Шинэ гарнитур үүсгэхэд плитканы доор суурилуулсан зуухтай 600 мм хэсэг орно.
2. Өмнө хадгалсан плиткатай шүүгээг сонгоод **Шүүгээний загвар → Плитка + суурилуулсан зуух** сонгоно. Хуучин `hob` загварт зуухыг автоматаар нэмээгүй; хадгалсан загвар хэвээр нээгдэнэ.
3. Өндөр шүүгээнд **Дунд хэсэгт суурилуулсан зуух** сонгоно. Өргөн 600 мм, гүн 580–650 мм шаардлагатай. Зуухны нүхэнд давхар шургуулга оруулахгүй.
4. Сонгосон шүүгээний **Зуух**, **Плитка**, **Угаалтуур**, **Холигч цорго**, **Хаалганы навч**, **Шургуулганы нүүр**, **Бариул**, **Тавцан**, **Хөл, суурь**, **Дотоод бүтэц** хэсгүүдээс тухайн төрөлд хамаарах нь харагдана.
5. Хэсэг дээр дараад **Тохиргоо** эсвэл **Солих** сонгоно. Компьютерт баруун panel, утсанд доороос sheet нээгдэнэ. Утасны дээд зурвасыг доош 80 px чирж хаана; Escape, хаах товч, гадна талд дарах мөн ажиллана.
6. Хэмжээг **Дотоод бүтэц** эсвэл **Хэмжээ, байрлал өөрчлөх** хэсгээс тохируулна. Хэмжээ/байрлал тохирохгүй үед өмнөх хүчинтэй загвар хадгалагдана.
7. Нэг шүүгээний тавцангийн өнгө/материал өөрчлөгдөхөд тусдаа хэсэг болно. **Тавцан · нийт загвар** үйлдэл бүх тавцанд дахин нэг материал үйлчилнэ.
8. Одоогийн **Хадгалах**, өрөөнд байрлуулах болон **GLB татах** үйлдлүүд бүрэлдэхүүний тохиргоотой загварыг ашиглана. Native SKP нь өмнөх хөрвүүлэгч серверийн тохиргоог хэвээр шаарддаг.

## Өгөгдөл, геометр

- Хэмжээс, нүх, байрлал: мм. Three.js renderer: метр. Cabinet-ийн local +Z нь урд тал.
- `opening: "oven"`: тусгай угсрах нүхтэй шүүгээ. Доод шүүгээ плиткатай; өндөр шүүгээ зуухтай боловч плиткагүй.
- Зуухны их бие: 560 × 590 × 540 мм; 600 мм шүүгээний дотоод нүх 564 × 600 мм. Нүхний Y: доод шүүгээнд `height - 680`; өндөр шүүгээнд 900 мм.
- Cabinet shelves/fronts нь нүх рүү орохгүй. Зуух тусдаа нэртэй `Appliance-oven-*` group бөгөөд өөрийн нүүр, шил, бариултай. Cabinet-тай хамт зөөх, эргүүлэхэд attachment салж үлдэхгүй.
- Плитканы countertop огтлол 500 × 400 мм; суулгах их бие 498 × 398 мм; гаднах шил 520 × 440 мм. Доод хэсгийн зуухтай ижил local X=0 тэнхлэгтэй, биетүүдийн хооронд босоо зайтай.
- `snapAppliance()` / `replaceComponent()` буруу төрөл, нүх, хэмжээ, давхцал илэрвэл алдаатай хамт өөрчлөгдөөгүй эх kitchen объектыг буцаана.
- `components?: [{ type, model, color?, finish?, size? }]` нь cabinet JSON дотор хадгалагдана. Хуучин version:1 загварт optional. `getComponents()` нь бодит cabinet төрлөөс бүрэн category tree гаргана. Хаалга, шургуулганы нүүрний model/color/finish нь бие даасан override; нийт appearance удирдлага тэдгээрийг сонгосон хүрээнд шинэчилнэ. Бариулын загвар өмнөх handleStyle талбарт мөн тусна.
- `parseKitchen()` төрөл, model, өнгө, давтагдсан category-г шалгаж, зөвшөөрсөн талбаруудыг л хадгална. Өөрчлөлт API, account library болон Room Planner snapshot-д дамжина. JSONB бүтэц ашигладаг тул SQL migration хэрэггүй.
- Үйлдвэрлэгчийн тодорхой SKU, үнэ болон component бүтээгдэхүүний backend энэ төсөлд одоогоор байхгүй. **Солих** жагсаалт нь хэмжээ/төрлөөр шүүсэн процедур загварууд; бүтээгдэхүүний үнэ зохиож нэмээгүй. Бодит каталог холбоход `COMPONENT_OPTIONS` болон renderer-ийн model implementation-ийг өргөтгөнө.
- Дээрх хэмжээ нь зураглалын preset. Бодит бүтээгдэхүүн сонгоход тухайн үйлдвэрлэгчийн угсралтын нүх, агааржуулалтын үзүүлэлтийг catalog metadata-д оруулна.

## Гол файлууд

- `src/lib/kitchenAppliances.ts`: нэг эх үүсвэртэй зуухны нүх/их бие, fit validation, урд бариулын хэмжээ.
- `src/lib/kitchenComponents.ts`: component tree, procedural загварууд, compatible filtering, atomic replacement.
- `src/three/KitchenAssemblyMesh.tsx`: cabinet opening, appliance geometry, өөрчлөгддөг материал.
- `src/components/KitchenOptionsPanel.tsx`: category rows, тохиргоо, солих grid.
- `src/components/KitchenComponentSheet.tsx`: дахин ашиглах accessible desktop/mobile modal.
- `tests/kitchen-components.test.cjs`: slot fit, бодит mesh-ийн давхцал, countertop cutout, JSON roundtrip, bounds болон export regression.

## Шалгасан хүрээ

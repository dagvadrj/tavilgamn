# Нэгдсэн гарнитурын редактор

`/kitchen` дээр модуль байрлуулах болон гарнитурын тохиргоо нэг `ModularKitchen` өгөгдөл ашиглана. Өнгө солих, хэлбэр өөрчлөх, хадгалах үед шүүгээний ID, хэмжээ, байрлал алдагдахгүй.

## Суулгах

1. ZIP доторх шинэ/өөрчлөгдсөн файлуудыг төслийн ижил замд хуулна. Эсвэл PATCH-ийг өмнөх modular MVP хувилбар дээр `git apply` ашиглан хэрэглэнэ. ZIP болон PATCH-ийг давхар хэрэглэх шаардлагагүй.
2. Supabase SQL Editor дээр `supabase/migrations/20260912125410_kitchen_garnitures.sql` файлыг нэг удаа ажиллуулна. SQL нь шинэ `kitchen_garnitures` хүснэгт, эзэмшигчийн RLS дүрэм, индекс, шинэчлэгдсэн огнооны trigger үүсгэнэ. Бусад хүснэгтийн өгөгдөл өөрчлөхгүй.
3. Одоогийн Supabase public URL, anon key, серверийн service role key тохиргоог ашиглана. Шинэ dependency эсвэл R2 файл шаардлагагүй.
4. `npm run typecheck`, `npm test`, `npm run build` ажиллуулна.

Энэ өөрчлөлтөөр production migration/deploy хийгдээгүй. SQL ажиллаагүй үед редактор нээгдэж, локал ноорог хадгалагдана; бүртгэлд хадгалах API алдаа харуулна. Амжилтгүй хадгалалтыг амжилттай гэж үзэхгүй.

## Хэрэглэх урсгал

- Шүүгээг чирэхэд хананд болон зэргэлдээ модульд таарна. Байршлын алдаа улаанаар харагдаж, боломжгүй шилжилт буцна.
- Өнгө, материал, хаалганы загвар, бариулыг сонгосон модуль, доод/өндөр хэсэг, дээд хэсэг эсвэл бүх гарнитурт хэрэглэнэ. Тавцангийн материал тусдаа.
- Шулуун, L баруун, L зүүн хэлбэрийн товч одоо байгаа модуль, материалуудыг хадгалан дахин байрлуулна. Багтахгүй бол өмнөх хэлбэр үлдэнэ.
- Хаалга, шургуулга нээж харах боломжтой. Ил тавиур, угаалтуур, плитка хуучин гарнитурын редактортой нэг загварын хэсэг болсон. Угаалтуур/плиткад доод шүүгээний өргөн 600/800 мм байна. Эдгээр нь каталогийн бодит appliance SKU/үнэтэй холбогдоогүй дүрслэлүүд.
- **Хадгалах** → бүртгэлийн **Гал тогооны гарнитур** хэсэг. **Шинэ гарнитур** → шинэ бие даасан загвар. Ижил загварыг дахин хадгалах үед шинэ давхардсан мөр үүсгэхгүй.
- **Хадгалаад өрөөнд байрлуулах** → `/planner?kitchen=<id>`. Өрөөнд сул зай олдвол бүх гарнитурыг нэг объект болгон оруулна. Эсвэл planner-ийн **Өөрийн загвар · гарнитур** хэсгээс сонгоно.
- Өрөөний загварыг хадгалах товч нь өмнөх шиг энэ төхөөрөмжийн өрөөний санг ашиглана. Гарнитурын сан Supabase-д хэрэглэгчээр хадгалагдах тул өөр төхөөрөмжөөс мөн харагдана.

## Хэмжээний баталгаа

Редактор ба RoomPlanner нь `KitchenAssemblyMesh`-ийн ижил `CabinetBody` / `KitchenTops` геометр ашиглана. Миллиметрийг метр болгох `/1000` хөрвүүлэлтээс өөр scale байхгүй. Хаалттай хаалга, бариул, тавцангийн 20 мм илүү гарсан хэсэг, угаалтуурын цорго болон дээд ирмэгийг `kitchenEnvelope` тооцно.

Жишээ: 5 × 600 мм шүүгээтэй, урт бариултай эх загварын гадна хэмжээ **3000 × 622 × 2120 мм**. 600 мм нь шүүгээний их биеийн гүн; 622 мм нь бариулыг багтаасан бодит гадна гүн. Товчин бариултай бол 631 мм гүнтэй. Өрөөнд багтаахын тулд эдгээр хэмжээг багасгахгүй.

Өрөөний нэг объект дотроо гарнитурын бүтэн JSON хуулбарыг хадгална. Эх гарнитурыг дараа нь засах/устгах нь өмнө байрлуулсан өрөөний хуулбарыг өөрчлөхгүй. Шинэ хувилбарыг оруулах бол өмнөхийг хасаад шинэ хадгалсан гарнитураа байрлуулна.

Collision нь модуль болон тавцан тус бүрийн эзлэх талбайгаар шалгана. L хэлбэрийн хоосон зайд өөр тавилга/багана багтаж болно. Багана, товойсон хана, бусад тавилга болон нам таазтай давхцвал оруулахгүй. Өрөөний exact-fit байрлал 250 мм торонд таараагүй байсан ч хананд тулгасан байрлалыг шалгана.

## Өрөөний plan зураг

“Өрөөний бодит хэмжээ, хэлбэр” modal-ийн зурагт AB/BC, ханын хэсэг тус бүрийн Х дугаар ба мм хэмжээс, багана, тавилгуудын байрлал харагдана. Богино ханын дугаарыг доорх хэмжээсийн жагсаалттай тулгана. Зөв хэмжээний өөрчлөлт, багана устгал зурагт тэр даруй хэрэгжинэ. Алдаатай утга 3D болон plan-д хэрэгжихгүй.

## Шалгалт

- `kitchen-integration.test.cjs`: шулуун/L хувилбарын материал ба ID, JSON validation, бодит Three.js геометрийн Box3 хүрээ, хэмжээгүй сунгалтаас хамгаалсан байршуулалт, L-ийн хоосон зай, багана, plan зураг.
- `kitchen-library.test.cjs`: API owner filter, хадгалалт, буруу өгөгдөл, DB алдаа, хэрэглэгч солигдох үеийн хуучин хариу болон stale refresh.
- `kitchen-db.test.cjs`: PGlite дээр SQL migration-ийг ажиллуулж owner CRUD, anonymous denial, ownership transfer rejection, timestamp шалгана.
- Браузер/WebGL болон production Supabase дээр end-to-end шалгалт хийгдээгүй. Одоогийн үнэлгээний каталоггүй шүүгээнд үнэ зохиож нэмээгүй.

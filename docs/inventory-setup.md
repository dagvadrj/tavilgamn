# Нөөц болон холбоо барих хэсгийг идэвхжүүлэх

## Өгөгдлийн сан

Одоо ашиглаж буй Supabase төслийн SQL Editor дээр
`supabase/migrations/202609060001_inventory_contact.sql` файлыг нэг удаа ажиллуулна.
Энэ нь одоогийн `products` дахь барааг `furniture_models` руу шилжүүлж,
`in_stock` баганыг integer болгоно. Барааны бүх мэдээлэл нэг хүснэгтэд хадгалагдана.
`product_id` нь хуучин холбоос, сагс, өрөөний загваруудын ID-г хэвээр хадгална.
Хуучин хүснэгт `products_legacy_backup` нэртэй, апп-аас унших эрхгүй нөөц хуулбар болно.
Хуучин каталог синхрончлох trigger, функцийн хэрэглээг зогсооно.
Migration нь одоогийн orders/payment хүснэгтүүдийг шаарддаг.
Migration нь нэг transaction дотор ажиллана: алдаа гарвал бүх өөрчлөлт буцна.

Олон зурагтай бүтээгдэхүүний gallery ашиглахын өмнө дараагийн
`supabase/migrations/202609090001_product_gallery.sql` migration-ийг мөн нэг удаа ажиллуулна.

Migration-ийг шинэ кодыг нийтлэхээс өмнө хэрэгжүүлнэ. Migration хийгээгүй үед
каталогийн шинэ талбарууд байхгүй учраас бараа унших, хадгалах үйлдэл ажиллахгүй.
Эхлээд migration, дараа нь шинэ апп-ийг ажиллуулах шаардлагатай.

## Админы оруулах мэдээлэл

- “Бүтээгдэхүүн → Засах” хэсэгт бараа бүрийн **боломжтой үлдэгдэл** оруулна.
- Тоо нь `furniture_models.in_stock` дотор бүхэл тоогоор хадгалагдана.
- Нэр, тайлбар, үнэ, зураг, хэмжээ, өнгө, материал, дэлгүүр, үнэлгээ, 3D файл бүгд `furniture_models` дотор байна.
- Тоо нь өнгө, материалаар салгаагүй, тухайн барааны нийт боломжтой ширхэг.
- Хуучин “нөөцтэй” төлөвөөс тоо таахгүй: үлдэгдэл нь хоосон/null байна.
  Тооллого оруулах хүртэл тухайн барааг захиалах боломжгүй.
- Хуучин “нөөцгүй” төлөвтэй бараа 0 үлдэгдэлтэй болно.
- Migration-ээс өмнөх захиалгуудын нөөцийг автоматаар дахин хасахгүй.
  Эхний тооллогод эдгээр захиалгад зориулан тусгаарласан барааг хасаж оруулна.
- 3D загвар шинээр оруулахдаа мөн үлдэгдлийг оруулна.

## Захиалгын нөөц

Захиалга үүсэх үед боломжтой үлдэгдлээс хасаж, захиалгад зориулан хадгална.
Төлбөр баталгаажих үед дахин хасахгүй. Захиалгын төлөв `cancelled` болоход
энэ хувилбараар тусгаарласан нөөцийг нэг удаа буцаана. Хүлээгдэж буй захиалга
хугацаагаар автоматаар цуцлагдахгүй; нэхэмжлэх/төлбөрийг тулгаж байж цуцална.
Одоо байгаа админ интерфэйст цуцлах шинэ үйлдэл нэмээгүй.

Нөөц зэрэг өөрчлөгдвөл админ хуучин тоог дарж хадгалахгүй:
жагсаалтаа шинэчлээд барааг дахин нээх шаардлагатай.

## Холбоо барих

Зурвас `contact_messages` хүснэгтэд хадгалагдаж, “Удирдлага → Ирсэн зурвас”
хэсэгт зөвхөн админд харагдана. Имэйл автоматаар илгээхгүй; админ илгээгчийн
имэйл холбоосоор хариу бичиж болно. Нэг имэйлээс 15 минутад 5 зурвас хүлээн авна.

## Шалгалт

`npm test` нь нөөцийн дүрэм, захиалга, төлбөр болон PGlite дээр жинхэнэ SQL
migration/trigger-үүдийг ажиллуулж шалгана. PGlite тест нь үйлдлийг цуваагаар
гүйцэтгэдэг; бодит PostgreSQL-ийн олон холболтын ачааллын тест биш.
`npm run typecheck`, `npm run lint`, `npm run build` мөн ажиллуулна.

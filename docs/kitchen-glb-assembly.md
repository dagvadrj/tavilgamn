# GLB шүүгээ, эд ангийн угсралт

Planner нь бэлэн GLB загваруудыг харуулна. GLB холбогдоогүй хуучин шүүгээ 2D төлөвлөгөөнд хадгалагдах бөгөөд 3D дээр загвар сонгох төлөвтэй байна. Админд оруулсан бодит загварын материал, өнгө харагдана.

## Ямар хэсгийг тусдаа файл болгох вэ?

Их бие, доторх хөдөлгөөнгүй тавиуруудыг нэг GLB-д үлдээж болно. Хэрэглэгч сольдог хаалга, шургуулгын нүүр, бариул болон нэмэлт тоноглолыг тусдаа GLB болгоно. Геометр өөр бол тусдаа GLB; зөвхөн өнгө/texture өөр бол нэг GLB-г дахин ашиглаж `materialId` сонгоно. Бүтэн угсарсан тавилгын GLB хувилбараар бүх тавилгыг солих боломж мөн бий.

Админ → Гал тогооны материал хэсэгт зориулалтыг `front` (хаалга), `handle` (бариул), эсвэл `general` гэж бүртгээд PNG/JPG baseColor, normal, roughness, metalness зураг холбоно. Эд ангийн тохиргоонд «Энэ GLB-ээр материалын хувилбар нэмэх» дарж материалыг сонгоно. Planner-ийн одоогийн эд ангийн сонголт энэ хувилбарыг хадгална. Материал зөвхөн тухайн эд ангид үйлчилнэ; хаалганы өөрчлөлт child бариулыг буддаггүй. UV хэвээр үлдэнэ, texture-гүй материал хуучин diffuse map-ийг цэвэрлэнэ.

Нээх хөдөлгөөн: hinge/Y/±100°, эсвэл slide/Z/400 мм. Нугасны цэгийг эд ангийн local origin-оос мм-ээр тохируулна. Бариулын parent slot-ыг хаалга болгоно. Нээх/хаах нь 0.45 секундийн буцааж эргүүлж болох хөдөлгөөнтэй; reduced-motion тохиргоог дагана. Бүтэн GLB-ийн authored animation нэрийг мөн тохируулж болно. Угсарсан GLB экспорт хөдөлгөөний clip-үүдийг хадгална; SKP нь тухайн үеийн хөдөлгөөнгүй байрлалыг авна.

Merchant-ийн GLB таталт зөвхөн worker-оор бэлдсэн Standard GLB өгнө. Бэлэн биш үед экспортын хүсэлт өгч хүлээнэ; шахсан web GLB рүү буцаж шилжихгүй. Worker-ийн KTX хэрэгсэл `KTX_BIN`, CLI `--ktx-bin`, эсвэл local `.tools/ktx/bin`-ээс олдоно.

Хаалга тус бүр өөр slot байна. Ижил GLB-г хоёр slot-д холбож хоёр хаалга үүсгэнэ. Хаалга бүрийн бариул өөрийн parent slot-д холбогдоно. Тусдаа файл гэдэг нь өрөөнд тавих тусдаа тавилга гэсэн үг биш.

## Өгөгдлийн зохион байгуулалт

`20261020134417_separate_kitchen_model_library.sql` нь гал тогооны мөрүүдийг ID, архивын төлөв, файлын түүхтэй нь `kitchen_models` руу шилжүүлнэ. Ерөнхий каталог `furniture_models`-оос уншина. `model_registry` нийтлэг файлын түүхийн холбоосыг хадгална. `model_records` нь зөвхөн серверийн файл хүргэлт, төлөв, цэвэрлэгээний шалгалтад ашиглах read-only view. Шинэ хүснэгтүүд RLS-тэй, service role-оор хандана. Дараагийн reference guard migration нь merchant store-ийн FK-г хадгална.

| Хадгалах газар | Агуулга |
| --- | --- |
| `kitchen_models` | Их бие болон эд анги бүрийн файл, бодит хэмжээ, зураг, боловсруулалтын төлөв |
| `kitchen_models.specifications` | Эд ангийн `type: kitchen-part:door`, `kitchen-part:handle` зэрэг төрөл; `assembly: connector-origin` |
| `kitchen_models.glb_validation` | Upload-аас шалгасан node нэрс, хэмжээ, assetRole |
| `kitchen_module_variants.configuration.assembly` | Slot, parent, anchor, байрлал, хөдөлгөөн, зөвшөөрсөн GLB хувилбарууд |
| Хадгалсан дизайны `cabinet.partSelections` | `slotId → optionId`; optional slot-ийн хоосон утга нь салгасан хэсэг |

URL-г дизайнд хадгалахгүй. Админ API нь model ID-г шалгаж, каталогийн API одоогийн бэлэн файл/зургийн URL-г гаргана. Архивлагдсан буюу боловсруулалт дуусаагүй сонголтыг хэрэглэгч сонгохгүй. Шинэ slot, option code нь хадгалсан дизайнтай холбоотой тул нийтэлсний дараа тогтвортой байлгана.

## GLB origin ба байрлал

- Метрээр экспортлоно. +Y дээш, +Z нүүр.
- Их биеийн origin нь шалан дээрх доод төвд байна.
- Хаалганы GLB origin-ийг нугасны холболтын цэгт, бариулын origin-ийг бариулын бэхэлгээний цэгт байрлуулна.
- Blender-ийн Empty node-уудыг `anchor_door_left`, `anchor_handle` гэх мэт давхардахгүй нэрээр экспортлоно.
- Хаалга slot үндсэн их биеийн anchor-д, бариул slot хаалганы GLB доторх anchor-д холбогдоно. Хаалга нээгдэхэд бариул parent-аараа хамт хөдөлнө.
- Anchor байхгүй бол parent-аас X/Y/Z байрлалыг мм-ээр, эргэлтийг градусаар заана. Эд ангийг тус тусад нь төвлөрүүлж эсвэл автоматаар сунгахгүй.
- Үндсэн GLB дотор сольж буй хаалга хамт орсон бол `hideNodes`-оор хуучин хаалганы mesh-ийг нууна. Anchor болон түүний эцэг node-ийг нууж болохгүй.

## Админы ажиллагаа

1. **Гал тогооны GLB нэмэх** хэсэгт бүтэн шүүгээ/их бие эсвэл солигдох эд ангийн зориулалтыг сонгоно.
2. Их биед canonical module, эд ангид бодит Ө/Өн/Г хэмжээг мм-ээр оруулна. Anchor-тай их биед нэртэй node гэсэн сонголтыг идэвхжүүлнэ.
3. GLB preview дээр хэмжээ, +Z нүүр, origin-ийг шалгаад upload хийнэ. Worker дууссаны дараа каталогийг шинэчилнэ.
4. Шүүгээний variant-ийг сонгоод **Солих эд анги · Style / Color** хэсэгт slot нэмнэ. Бариулд хаалга parent-ийг сонгоно.
5. Slot бүрт зөвшөөрсөн GLB сонголтууд, үндсэн сонголт, нэр/өнгө/загвар, anchor эсвэл мм байрлалыг оруулна.
6. Хаалганд hinge тэнхлэг/градус, шургуулганд slide тэнхлэг/мм заана. GLB animation upload одоогоор шаардлагагүй: хөдөлгөөнийг slot өгөгдлөөр удирдана.
7. Угсралтын 3D preview дээр байрлал, нээлтийг шалгаад **GLB холбох** дарна. Өмнөх variant дээр **Эд анги засах** товчоор өөрчилж болно.

## Хэрэглэгчийн ажиллагаа

Тавилга сонгоход зүүн талд Modify, Replace, Open, Zoom, Position, Duplicate, Remove гарна. Modify дотор эд ангийг сонгоод Загвар / Өнгө жагсаалтын зургаар GLB-г солино. Хөдөлгөөн тохируулаагүй статик загварт Open идэвхгүй байна. Баруун тал нь камер болон өрөөний жижиг зурагт зориулагдана.

## Боловсруулалт ба шалгалт

GLB upload болон worker-т `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME` шаардлагатай. GLB уншихад эдгээр тохиргоогоор signed URL ашиглах эсвэл тухайн bucket-ийн HTTPS `R2_PUBLIC_BASE_URL` ашиглаж болно. Cloudinary-ийн өмнө нь upload хийсэн зураг үзүүлэхэд зөвхөн `CLOUDINARY_CLOUD_NAME` хэрэгтэй; зураг шинээр upload хийхэд `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` нэмэлтээр шаардлагатай. Worker ажиллах орчинд Blender болон texture шахалт ашиглавал KTX хэрэгсэл байна. Нууц түлхүүрүүдийг repository-д хадгалахгүй.

Анхны 2026-10-13 шалгалт: 607 тест, TypeScript, ESLint, production build амжилттай. Live Supabase-аас 27 модуль, 3 бэлэн variant уншигдсан. Cloudinary account болон R2 bucket нэрийг хадгалсан asset замаас тогтоож local тохиргоонд нэмсэн; R2 access тохиргоог хэрэглэгч `.env.local`-д нэмсний дараа гурван thumbnail, гурван үндсэн GLB, гурван preview local API-аас 200 хариу өгсөн. GLB бүрийн binary header, нийт урт, JSON бүтэц шалгагдсан. Гурван GLB-ийг браузерийн 3D зурагт зэрэг байрлуулж харагдацыг шалгасан. Ачаалалтын өөрчлөлтийн дараах 26 холбоотой тест, TypeScript, ESLint амжилттай. Blender local орчинд байхгүй тул Blender export-ийг end-to-end ажиллуулаагүй; бодит GLB prune болон anchor transform audit тестээр шалгагдсан. Нийт stylesheet шалгалтын хуучин CRLF formatting зөрүү энэ өөрчлөлтөөс тусдаа байна.

Ачаалж буй болон алдаатай GLB-ийн мэдэгдлийг зөвхөн сонгосон шүүгээнд харуулна. Алдаа гарвал «Загвар ачаалж чадсангүй» болон дахин оролдох үйлдэл гарна; ачаалаагүй тавилгыг хиймэл mesh-ээр орлуулахгүй.

Браузер дээр тавилгын бодит GLB mesh дээр дарж зүүн удирдлага нээгдэх, Replace-аар GLB болон хэмжээ хамт солигдох, Undo/Redo хийхэд сонголт ба удирдлага хадгалагдахыг шалгасан. Нэмэлт layout шалгалтын 5 тест амжилттай.

Blender export нэртэй Empty node-уудыг хадгална. Delivery болон preview шахалт `prune --keep-leaves true` ашиглана. Worker нь assembly/part загварын source болон шахсан хоёр файлын anchor-уудын world transform-ийг харьцуулж, алга болсон эсвэл шилжсэн бол нийтлэхгүй. Эд ангийн connector origin-ийг доод төв рүү шилжүүлэхгүй.

Угсралтын тестүүд нь parent хөдөлгөөн, GLB сольсон үед их биеийн материал хадгалагдах, optional хэсэг салгах, дизайн хадгалах/сэргээх, API model reference, архивлагдсан сонголт болон anchor export-ийг шалгана. Хуучин үйлдвэрлэлийн геометрийн тест fixture нь planner-ийн runtime renderer-ээс тусдаа байна.

## Хялбар угсралтын урсгал

Их бие → хийц → хаалга/шургуулга → бариул → 3D шалгалт → хадгалах. Хоёр хаалгатай хийцэд хоёр slot заавал холбоно. Ижил GLB-г хоёр талд ашиглаж болно; баруун хаалгыг X тэнхлэгээр толин тусгал болгоно. Хоёр хаалга урагш нээгдэхээр local хөдөлгөөнийг тохируулна. Бодит хэмжээг сунгахгүй; нугасны origin, байрлалыг preview дээр шалгана. Шинэ эд анги upload хийсний дараа угсралтын draft руу буцаж холбогдоно. Worker дууссаны дараа хадгална.

`assemblyMode: parts` үед сервер хаалга, шургуулгын тоо болон GLB бүрийн төрөл, бэлэн төлөвийг шалгана. Бүтэн GLB-д `authored` горимыг ашиглана. Сангийн жагсаалтыг нэр, ангилал, боловсруулалтын төлөв, өргөнөөр шүүнэ.

Worker нь `claim_furniture_model_job`, `claim_kitchen_model_job` болон хоёр сангийн export RPC-г ээлжлэн шалгана. Шилжилтийн дараа worker-ийг шинэ кодоор дахин эхлүүлнэ. Файлын R2 зам, `/api/models/files/:id/:filename` холбоос өөрчлөгдөхгүй.

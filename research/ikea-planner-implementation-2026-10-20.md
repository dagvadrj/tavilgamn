# IKEA судалгааны planner хэрэгжүүлэлт

2026-10-20 · [Судалгааны эх файл](./ikea-room-planner-deep-research-2026-10-20.md)

Судалгааны §7 дахь таван чиглэлийг одоогийн planner-ийн кодод хэрэгжүүлж, өмнө байсан өрөө байгуулах, хадгалах болон засварлах урсгалтай холбов. IKEA-ийн код, каталог, asset-ийг хуулж оруулаагүй.

## 1. Каталог ба model contract

- Каталогийн төрөл, mount, opening, өргөн/өндөр/гүн нь scene дахь шүүгээтэй таарна. Өөр хэмжээтэй SKU-г сунгаж ашиглах fallback-ийг хассан.
- Доод/дээд булангийн модулийг гүн болон төрлөөр нь тусад нь шалгана; каталогийн дээд буланг оруулахад ханын шүүгээ үүсгэнэ.
- Ready биш, идэвхгүй эсвэл GLB validation алдаатай хувилбар тохирох model гэж сонгогдохгүй.
- Өмнө хадгалсан SKU каталогоос алга болсон бол өөр бараагаар далд солихгүй. Бэлэн бус төлөвт хэвээр танигдана.
- Supabase-аас аль хэдийн уншдаг `glb_validation`-ийг модулийн хэмжээнд дахин тулгаж, validation асуудлыг клиентэд дамжуулна. Schema болон өгөгдлийн өөрчлөлт хийгээгүй.
- Variant, product, model ID нь BOM/CSV болон сонгосон бүтээгдэхүүний дэлгэрэнгүйтэй холбоотой.

Гол файлууд: `src/lib/kitchenModuleCatalog.ts`, `src/lib/kitchenModuleCatalogServer.ts`, `src/lib/kitchenCatalogInsertion.ts`.

## 2. Байрлуулах дүрэм

- Editor, оруулах үйлдэл, санал үүсгэгч ижил хаалга/цонхны нээлхийн geometry ашигладаг.
- Цонхны тавцангийн доорх шүүгээг зөвшөөрч, нээлхийг хаасан өндөр/дээд шүүгээг хориглоно.
- Хаалга хаалттай байсан ч дотогш нээгдэх зайг хадгална. Нээлтийн зайг болгоомжтой тэгш өнцөгтөөр нөөцөлдөг; яг хаалганы нумын solver биш.
- Доод/өндөр шүүгээ шаланд; дээд шүүгээ хананд, зөв өндөрт байрлана. Булангийн шүүгээ хоёр перпендикуляр ханатай хүрэлцэнэ.
- Kitchen opening-д өндөр, цонхны тавцангийн түвшин, хаалганы дотогш/гадагш нээгдэх сонголт нэмсэн. Хадгалах, parse болон 3D ханын нээлхий ижил утгуудыг ашиглана.
- Ерөнхий room planner-ийн collision шалгалтад хаалга/цонхны бүс нэмсэн. Залгаатай өрөөнүүдэд бүсийг өрөө тус бүрийн координатаас шилжүүлнэ.
- Асуудлын жагсаалтаас тухайн тавилга эсвэл өрөөний тохиргоог нээж засна.
- Тулгууртай эдлэлийг солихдоо дээрх эдлэлүүдийн холбоос, багтах эсэхийг дахин шалгана.

Гол файлууд: `src/lib/kitchenPlacement.ts`, `src/lib/kitchenSpace.ts`, `src/lib/kitchenWallPanels.ts`, `src/three/collision.ts`, `src/three/roomPlacement.ts`.

## 3. Asset ба renderer

- GLB-г decode хийсний дараах бодит bounds-ийг хэмжэстэй тулгана. 5 мм-ийн tolerance ба баталгаажуулсан бариулын урд projection-ийг тооцно.
- Хэмжээ зөрсөн файлыг scene-д хавсаргахгүй. Kitchen GLB-г физик хэмжээгээр байрлуулж, буруу харьцаагаар сунгахгүй.
- Тохирох model байхгүй үед хэмжээсийн бүдэг хүрээ, сонгоход бэлэн бус тайлбар гарна.
- Шинэ SKU ачаалж байх үед өмнөх SKU-г шинэ бараа мэт харуулахгүй. Дутуу/алдаатай model export-ready болохгүй.
- Өмнө байсан URL cache, shared in-flight promise, model clone, материалын тусдаа instance, reference release, texture sampling, Draco/Meshopt/KTX2 delivery болон versioned worker pipeline-ийг хадгалсан.
- Preview болон өрөөнд оруулсан kitchen assembly мөн ижил contract ашиглана.

Гол файлууд: `src/lib/modelPlacement.ts`, `src/three/GLBFurnitureMesh.tsx`, `src/three/KitchenCabinetGLB.tsx`, `src/three/KitchenAssemblyMesh.tsx`.

## 4. Editor ба худалдааны мэдээлэл

- Өмнө байсан дөрвөн алхамтай room builder, хэмжих нэгж, flip/rotate, undo/redo, duplicate болон хэмжээсийн хэрэгслүүдийг хадгалсан.
- Kitchen editor-т хажуугаас харах товч нэмсэн.
- Kitchen бүтээгдэхүүн солихдоо ижил байрлалд шалгаж, шинэ хэмжээ багтахгүй бол өөр газарт далд шилжүүлэхгүй, өмнөх загварыг хадгална.
- Ерөнхий room planner-т ижил ангиллын бодит бүтээгдэхүүнүүдээр байранд нь солих самбар нэмсэн. Нөөц, mount, өрөөний хил, ceiling, openings, бусад тавилга, тулгуурын холбоосыг шалгана.
- Солих үйлдэл instance ID болон сонголтыг хадгалж, хуучин model ID-г цэвэрлэнэ. Нэг update нь өмнөх undo/redo урсгалд орно.
- Сонгосон kitchen хувилбарын code, каталогийн үнэ, бүтээгдэхүүний холбоос харагдана.
- BOM нь assembly-ийн сонгосон эд ангиудыг бүртгэнэ. Хассан parent-ийн dependent эд ангиуд жагсаалтад үлдэхгүй.
- `partsIncluded` эсвэл `partsPricedSeparately` баталгаажаагүй хэсгийн үнийг тодруулах төлөвт үлдээнэ. Тодорхойгүй үнийг 0 төгрөг болгож нийт үнэ гэж үзүүлэхгүй.

Гол файлууд: `src/lib/roomProductReplacement.ts`, `src/features/room-planner/components/RoomProductAlternatives.tsx`, `src/features/kitchen-planner/components/KitchenSelectionPanel.tsx`, `src/lib/kitchenBom.ts`.

## 5. Тав хүртэл санал

- Олон layout family, шүүгээний дарааллаас candidate үүсгэж, geometry болон hard constraints-аар шүүнэ.
- Тэнцвэр, төсөв, хадгалалт, бэлтгэх тавцан, сул зайгаар эрэмбэлнэ. Ажлын урсгал, бага өөрчлөлтийн өмнөх зорилгууд мөн үлдсэн.
- Хэрэглэгч каталогийн өөр шүүгээ санал болгох сонголтыг асаавал бодит module/SKU/хэмжээтэй төсөв болон хадгалалтын нэмэлт candidate үүсгэнэ. Төхөөрөмжийг солихгүй.
- Бүтээгдэхүүний төсвийн хязгаар, төхөөрөмжийн байрлал түгжих, каталогт хэв маяг бүртгэлтэй бол түүгээр шүүх боломжтой.
- Өөр SKU эсвэл өнгө нь ижил geometry-г дахин нэг санал болгохгүй. Ижил шкафуудын instance ID солигдсоныг давхар тоолохгүй.
- Бүтээгдэхүүний тоо ширхэг тухайн SKU-ийн нөөцөөс хэтэрсэн шинэ сонголтыг хасна.
- Санал бүр шалтгаан, хэмжсэн үзүүлэлт, сольж буй бүтээгдэхүүний тоо, бүтээгдэхүүний дүн/үнэ дутуу төлөв, үнэ тодруулах мөрийг харуулна.
- Хангалттай valid, давуу талтай, ялгаатай candidate байхгүй бол тав болгож давтахгүй. Хасагдсан нөхцөлийг тайлбарлана.

Гол файлууд: `src/lib/kitchenDesignSuggestions.ts`, `src/features/kitchen-planner/components/KitchenDesignSuggestions.tsx`.

## Бодит каталогийн үлдсэн хязгаар

Локал public API snapshot-д **35 модуль, GLB-тэй 2 хувилбар** байна. Хоёулаа доод шүүгээ; нэг нь physical validation-тай, нөгөө нь decode үеийн хэмжээсийн хамгаалалтаар шалгагдана. Эдгээрийн худалдан авах үнийг public бүтээгдэхүүний каталогтой бүрэн холбож тогтоогоогүй байна.

Иймээс дээд/өндөр/булангийн бодит GLB asset, үйлдвэрлэлийн зөв хэмжээс, product/SKU, баталгаатай үнэ болон багцын эд ангийн үнэ бүрдүүлэх контентын ажил үлдэнэ. Одоогийн код энэ дутуу мэдээллийг өөр model, сунгасан mesh, зохиомол үнэ эсвэл давхардсан таван санал ашиглан нөхөхгүй.

Фото/LiDAR-аар өрөө таних үйлчилгээ, ML training, IKEA-ийн backend эсвэл дотоод asset үүсгэх pipeline-ийг энэ хэрэгжүүлэлтэд бүтээсэн гэж тооцохгүй. Судалгаа эдгээрийн exact implementation-ийг тогтоогоогүй бөгөөд §7-ийн таван ажлын суурь шалгуурт ийм үйлчилгээ шаардаагүй.
